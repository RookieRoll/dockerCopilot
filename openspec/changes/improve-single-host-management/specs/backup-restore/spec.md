# Spec Delta

## Purpose

定义已有容器配置 JSON 备份、Compose 导出、备份文件管理和 JSON 恢复能力，确保文件可靠保存、旧备份可用，并让用户准确理解配置恢复范围与每个容器的执行结果。

## ADDED Requirements

### Requirement: 配置备份与导出能力保留
系统 SHALL 保留 JSON 配置备份与 Compose 导出，以及既有 JSON 文件的恢复兼容性。页面和结果 MUST 明确备份覆盖容器配置，不包含数据卷内容。恢复 SHALL 保持创建容器但不自动启动的既有行为。

#### Scenario: 导出已有容器配置
- **WHEN** 用户创建 JSON 或 Compose 备份
- **THEN** 生成对应格式的配置文件，结果说明配置备份范围，现有备份管理页面仍可列出该文件

#### Scenario: 恢复旧 JSON 备份
- **WHEN** 用户选择格式合法的既有 JSON 备份
- **THEN** 可以按其中配置创建容器，不要求先转换新格式，创建后不自动启动

### Requirement: 备份文件完整且不意外覆盖
创建备份 SHALL 使用不冲突的文件名，只有写入完整后才可在列表中作为成功文件出现。同日多次备份 MUST NOT 覆盖已有文件；失败时 MUST 保留已有备份。包含凭据的配置文件 SHALL 使用限制性读取权限，日志不得输出其正文。

#### Scenario: 同一天创建两次备份
- **WHEN** 用户连续成功创建两份 JSON 备份
- **THEN** 两份文件分别存在并可识别，不覆盖第一份

#### Scenario: 写入期间磁盘失败
- **WHEN** 备份写入中断或空间不足
- **THEN** 任务失败，不把未完成文件列为成功备份，不破坏已有备份

### Requirement: 备份不读取更新中间状态
系统 SHALL 协调配置备份与容器替换，避免将临时改名和未完成配置当作正常快照。无法取得稳定配置时 MUST 报告相关容器的冲突或未备份结果，不将不完整操作声明为完整备份。

#### Scenario: 更新过程中创建配置备份
- **WHEN** 某容器处于替换阶段且无法取得稳定配置
- **THEN** 备份结果明确指出该对象未备份或冲突，不能静默导出临时名称作为其正常配置

### Requirement: 恢复预校验与逐项结果
恢复 SHALL 在开始修改前验证文件结构；批量恢复 SHALL 记录每个容器的成功、失败或跳过。已有同名容器 MUST 被视为冲突，不自动覆盖。部分失败 MUST 在总结果中体现，并保留成功项和原始失败原因。

#### Scenario: 备份结构损坏
- **WHEN** JSON 备份无法解析或结构非法
- **THEN** 任务失败且不开始任何容器创建

#### Scenario: 恢复时容器重名
- **WHEN** 一个待恢复名称已存在而其他条目合法
- **THEN** 该项报告冲突，不删除或覆盖现有容器，其他可执行项具有各自结果

#### Scenario: 恢复过程中某镜像拉取失败
- **WHEN** 多个恢复条目中某项拉取失败
- **THEN** 该项保留失败原因，最终结果报告部分失败，不统一显示全部恢复成功

### Requirement: 接受任务与恢复完成分离
页面 SHALL 使用返回任务 ID 查询恢复或异步导出结果，只有达到成功终态才展示成功。旧同步备份接口 SHALL 维持返回时已完成或失败的语义。

#### Scenario: 恢复请求被接受
- **WHEN** 后端返回恢复任务 ID 且状态为 queued 或 running
- **THEN** 页面显示恢复中，不立即弹出恢复成功

### Requirement: 备份文件访问边界
列表、恢复和删除 SHALL 限制于配置的备份目录，拒绝路径穿越和链接逃逸，保持 JSON/YAML 文件管理能力。正在恢复使用的备份不得被并发删除；不存在或非法文件 SHALL 返回明确结果。

#### Scenario: 删除正在恢复的文件
- **WHEN** 某备份被活动恢复任务使用且用户请求删除
- **THEN** 返回冲突及关联任务，文件保持可用

#### Scenario: 请求目录外的备份
- **WHEN** 文件名或符号链接指向备份目录之外
- **THEN** 请求被拒绝，目录外文件不被读取或删除
