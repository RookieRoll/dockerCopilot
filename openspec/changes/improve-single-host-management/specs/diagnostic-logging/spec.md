# Spec Delta

## Purpose

让维护者通过一次请求或任务的标识还原容器操作、文件处理和外部请求的执行过程，准确定位失败阶段与原因，同时避免认证信息泄露和高频进度淹没有用日志。

## ADDED Requirements

### Requirement: 请求与任务日志可以关联
系统 SHALL 为请求提供可检索标识，后台任务各阶段 SHALL 使用稳定 taskId，并记录提交请求与任务的关联。日志 SHALL 包含适用的操作类型、容器或镜像标识、阶段、结果和耗时；短操作 SHALL 记录其结果。

#### Scenario: 根据页面错误定位更新
- **WHEN** 用户提供任务 ID
- **THEN** 维护者能在日志中找到接受、各执行阶段、最终结果以及提交请求的关联

#### Scenario: 改名失败
- **WHEN** 同步改名操作失败
- **THEN** 日志包含请求标识、目标容器、操作及原始原因，页面提供相同诊断标识

### Requirement: 失败原因与恢复结果完整
失败日志 MUST 保留经脱敏的原始错误原因、执行阶段、对象及耗时。恢复尝试和结果 SHALL 分别记录。网络错误 SHALL 区分程序版本查询、应用侧镜像检查和 Docker daemon 拉取，不能统一归为无上下文的更新失败。

#### Scenario: 远程版本连接重置
- **WHEN** 版本查询遇到 connection reset
- **THEN** 日志保留目标主机、网络原因、耗时和请求标识，不只留下非法 HTTP 状态码的堆栈

#### Scenario: 更新失败且恢复也失败
- **WHEN** 新容器启动失败，恢复旧容器又遇到名称冲突
- **THEN** 日志分别记录原始失败及恢复失败，并以同一 taskId 关联

### Requirement: 日志级别与噪声控制
系统 SHALL 记录 INFO 级任务接受、阶段变化和最终结果，WARN 级重试/陈旧结果/清理警告，ERROR 级失败及异常。逐层下载进度 SHALL 默认处于 DEBUG 且节流；高频成功查询不得重复输出与本次请求无关的配置详情。

#### Scenario: 默认日志下拉取大型镜像
- **WHEN** 默认 INFO 配置下收到大量下载进度消息
- **THEN** 日志可看到阶段和最终结果，不逐条输出全部下载进度

### Requirement: 认证与配置敏感信息脱敏
日志和公共错误响应 MUST NOT 输出 Authorization、Cookie、secretKey、仓库凭据、代理密码、URL 中的认证信息和敏感 token。请求体、容器环境变量、完整 inspect 和备份内容不得被默认转储。错误及异常日志 MUST 经过相同脱敏策略。

#### Scenario: 带认证头的请求发生 500
- **WHEN** 请求带 Bearer Token 和 Cookie 且 handler 失败
- **THEN** 日志包含必要请求摘要和错误，但不包含 Token、Cookie 原值或完整请求转储

#### Scenario: 错误文本包含代理凭据
- **WHEN** 网络错误文本中含用户名密码 URL 或 token 查询参数
- **THEN** 保留主机、错误类别和诊断价值，同时去除秘密值

### Requirement: 日志持久化与容量控制
系统 SHALL 同时提供标准输出和可配置的持久文件日志，支持日志级别、保留期和容量限制，自动清理符合策略的旧日志。文件日志写入失败 SHALL 向独立可用输出报告降级原因，不递归写入同一故障目标。

#### Scenario: 达到日志容量限制
- **WHEN** 日志目录达到配置容量上限
- **THEN** 轮转并清理最旧的已关闭日志，继续记录当前操作，避免无限增长

#### Scenario: 日志磁盘写入失败
- **WHEN** 文件日志不可写而标准错误输出可用
- **THEN** 标准错误输出报告日志降级，不能静默声称文件日志正常

### Requirement: HTTP 错误与业务错误分离
系统 MUST 使用合法 HTTP 状态码，业务错误码 SHALL 只出现在响应体。错误响应 SHALL 包含简明原因、稳定错误分类和诊断标识，不暴露内部堆栈；原始原因保留在脱敏日志中。

#### Scenario: 获取远端版本失败返回业务码 50001
- **WHEN** 版本逻辑产生业务码 50001
- **THEN** HTTP 响应使用合法错误状态，响应体可保留业务码并提供诊断标识，不触发 WriteHeader panic
