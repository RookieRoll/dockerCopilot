# Spec Delta

## MODIFIED Requirements

### Requirement: 手工端口配置生命周期与编辑
手工端口配置 MUST 以 Docker 成功返回的完整容器列表及更新操作保护状态作为生命周期校验依据。容器仍存在但处于停止状态时，配置 MUST 保留；容器已经从 Docker 列表中删除且不受更新或中断操作保护时，系统 MUST 在下一次稳定、成功的容器列表刷新中删除对应的孤儿配置。列表请求失败、快照期间发生改名/替换或原名称暂时缺失时 MUST 保留已有配置，待重新核对。已有配置 MUST 支持编辑、替换和清空删除。

#### Scenario: 容器删除后在列表刷新时清理配置
- **WHEN** Docker 容器已经被删除，且下一次 GET /api/containers 成功返回的稳定完整列表不再包含该容器名称，该名称也不受更新或中断操作保护
- **THEN** 系统删除该容器在 /data/config/container-port-overrides.json 中的配置项，后续列表响应不再返回该容器的 configuredPorts

#### Scenario: 停止容器不触发配置清理
- **WHEN** host 网络容器被停止但仍存在于 Docker 返回的全部容器列表中
- **THEN** 系统保留该容器的手工端口配置，容器重新启动后仍可继续使用

#### Scenario: Docker 列表失败时保留配置
- **WHEN** Docker 容器列表请求失败，系统无法确认容器是否仍存在
- **THEN** 系统不执行孤儿配置清理，并在下次成功刷新前保留已有配置文件内容

#### Scenario: 编辑已有端口配置
- **WHEN** 用户打开已经存在手工端口配置的 host 网络容器编辑入口
- **THEN** 弹窗预填已有的名称、端口和协议，用户修改后保存，系统以提交的新端口集合替换旧集合

#### Scenario: 删除全部端口配置
- **WHEN** 用户在编辑弹窗中删除全部端口并保存
- **THEN** 系统删除该容器的持久化配置项，容器卡片显示未配置状态和配置入口

#### Scenario: 更新临时改名期间刷新列表
- **WHEN** 旧容器已被临时改名，新容器尚未创建，页面刷新容器列表
- **THEN** 原名称对应的手工端口配置保持存在，更新完成后新容器继续获得该配置

#### Scenario: 清理使用了操作开始前的旧快照
- **WHEN** 容器列表获取到清理执行之间发生更新或改名
- **THEN** 系统放弃基于该旧快照的清理并重新核对，不删除仍有效的配置

#### Scenario: 更新中断后名称尚未恢复
- **WHEN** 服务重启且未完成更新使原名称暂时缺失
- **THEN** 配置继续受到保护，直到关联实例状态被确认稳定或用户明确完成处理

## ADDED Requirements

### Requirement: 改名与配置迁移一致
容器改名 SHALL 同步迁移已有手工端口配置；Docker 改名成功但配置迁移失败时 MUST 报告部分完成状态、保留原配置及重试所需标识，不得把配置丢失当作完整成功。改名与列表清理 SHALL 协调，避免清理迁移中的配置。

#### Scenario: 带手工端口的容器改名
- **WHEN** 用户成功将容器从旧名称改为新名称
- **THEN** 新名称关联原端口配置，原名称不留下重复生效配置

#### Scenario: 改名后配置迁移失败
- **WHEN** Docker 改名成功但文件写入失败
- **THEN** 页面和日志说明改名已发生但配置迁移未完成，原配置被保留且不会被孤儿清理立即删除
