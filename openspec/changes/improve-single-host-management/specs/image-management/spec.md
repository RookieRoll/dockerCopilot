# Spec Delta

## Purpose

保持单主机镜像查询、删除、批量清理和更新检查能力，让用户准确理解使用状态与检查结果，并避免清理操作干扰正在执行的容器更新和失败恢复。

## ADDED Requirements

### Requirement: 镜像列表和删除语义
系统 SHALL 保留镜像名称、tag、使用状态等现有查询能力。普通删除遇到使用冲突 SHALL 返回明确冲突；强制删除 MUST 由显式请求触发，不能因重试或错误处理自动升级为 force。

#### Scenario: 普通删除被使用的镜像
- **WHEN** Docker 拒绝删除仍被使用的镜像
- **THEN** 返回冲突和原因，不自动改成强制删除

### Requirement: 批量清理重新验证并逐项报告
系统 SHALL 保留无 tag 与未使用镜像清理，服务端执行前 MUST 重新验证目标资格，并返回每项成功、失败或跳过及汇总。清理操作 SHALL 在浏览器断开后保持可查询，不将部分失败声明为全部成功。

#### Scenario: 清理预览后镜像被使用
- **WHEN** 预览中的未使用镜像在执行前已被容器使用
- **THEN** 该项跳过或报告冲突，不按旧快照强制删除

#### Scenario: 批量清理部分失败
- **WHEN** 部分镜像删除成功而另一些被 Docker 拒绝
- **THEN** 任务报告各项结果和失败原因，页面显示准确数量

### Requirement: 活动更新的镜像保护
删除和清理 MUST 保护本服务活动更新或恢复正在使用的镜像及恢复旧容器所需镜像。显式 force 也不得绕过这项活动操作保护；冲突结果 SHALL 关联任务。

#### Scenario: 清理更新中的镜像
- **WHEN** 用户删除活动更新使用的目标镜像或用于恢复的旧镜像
- **THEN** 返回冲突或跳过结果及任务标识，镜像继续可供任务使用

### Requirement: 更新检查有新鲜度与失败信息
系统 SHALL 保留启动及定时镜像更新检查，避免同类检查重叠。检查失败时 SHALL 保留上次成功结果，同时提供最后成功时间、陈旧状态和错误原因；不能将失败直接表示为无需更新。

#### Scenario: 上次检测有更新而本次网络失败
- **WHEN** 镜像曾成功检测到更新，本次 registry 请求失败
- **THEN** 保留原更新提示并标记检查信息已陈旧，记录本次错误

#### Scenario: 第一次检查失败
- **WHEN** 镜像没有成功检查记录且 registry 不可达
- **THEN** 状态为未知或检查失败，不向用户承诺无需更新

### Requirement: 镜像仓库访问验证与诊断
应用侧镜像检查 MUST 默认验证 TLS 证书，允许显式配置受信任 CA。网络错误 SHALL 标识访问目标及请求用途，并区分应用摘要检查和 Docker daemon 镜像拉取；凭据不得写入日志。

#### Scenario: 仓库证书不受信任
- **WHEN** 仓库证书验证失败且未配置对应受信任 CA
- **THEN** 检查失败并记录 TLS 原因，不自动关闭证书验证

#### Scenario: 摘要查询成功但镜像拉取失败
- **WHEN** 应用获得远端摘要，而 Docker daemon 无法拉取镜像
- **THEN** 更新任务报告 daemon 拉取错误，不将摘要查询成功解释为镜像拉取成功
