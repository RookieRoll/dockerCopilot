# Proposal

## Why

dockerCopilot 的核心用途是单主机容器更新和端口快捷访问，现有容器操作、镜像管理、备份恢复、图标和自身升级也需要共同维护。当前后台任务、错误响应、配置生命周期和日志缺少一致的约定，导致更新成功与请求成功混淆、失败恢复不完整，以及排障时无法关联操作全过程。

## What Changes

- 保持单进程 Go 服务、嵌入式 React 前端及单容器部署，将已有功能整理为职责明确的业务模块；集中业务流程和文件读写，避免将全部依赖传入工具函数。
- 规范容器更新：预检查与配置快照、固定本次拉取的镜像身份、同容器操作互斥、启动验证、可判断失败时恢复旧容器、成功后清理旧容器。保持指定镜像/tag、单项和批量操作能力。
- 为更新、恢复、批量修改、备份导出及自身升级提供轻量的任务执行与状态记录；使用数据卷内文件持久化关键结果，页面刷新后可继续查询，进程重启后未完成任务明确标记中断。
- 统一错误响应与任务协议，区分请求被接受、任务完成、部分失败、旧容器恢复和清理警告；保留现有接口的兼容适配。
- 完善结构化日志：请求与任务关联、阶段与耗时、原始错误、恢复结果、认证信息脱敏、日志轮转及保留策略。
- 完善 JSON 配置备份、Compose 导出和 JSON 恢复的文件与结果语义，避免同日覆盖和接受任务即提示恢复成功。
- 完善镜像删除/清理的逐项结果、与更新操作的协调，以及镜像更新检查的安全网络访问和错误定位。
- 集中图标文件及映射维护，保证上传失败、并发写入和前端缓存的一致性。
- 保留端口展示、快捷访问与 host 网络手工配置，保护更新中的名称，避免临时改名期间误清理配置。
- 修正自身版本检查和升级流程，统一 RookieRoll/dockerCopilot 更新源、错误返回、包路径及安装验证。
- **BREAKING**（有限语义变更）：自身升级 PUT `/api/program` 的成功响应改为任务已接受，调用方需等待任务终态；新升级器拒绝缺少校验文件的旧 release。新前后端一起部署，外部调用方需适配；已有容器更新和恢复的接受语义保持不变。

## Capabilities

### New Capabilities

- `container-operations`: 容器列表、基础操作、可靠更新、操作互斥及批量执行结果。
- `background-tasks`: 后台任务的接受、执行、持久记录、查询、异常收尾与页面恢复。
- `diagnostic-logging`: 可关联的操作日志、错误分类、脱敏、日志保留及页面诊断标识。
- `backup-restore`: 配置备份、Compose 导出、文件管理及逐容器恢复结果。
- `image-management`: 镜像查询、删除/清理与更新检查的可靠行为。
- `icon-management`: 图标上传、映射持久化、读取及前端一致性。
- `program-update`: 自身版本查询、升级准备、安装、失败反馈及重启后版本确认。

### Modified Capabilities

- `container-port-links`: 扩展配置生命周期，保护更新中的容器名称，明确改名迁移及并发列表快照的处理。

## Impact

- 后端：`internal/handler`、`logic`、`svc`、`types`、`config`、`module`、`utiles`；新增专用业务与任务支持包，具体边界见 design.md。
- 前端：容器、镜像、备份、图标、版本页面及共享 API/任务查询逻辑。登录、主题、端口访问和现有页面能力保持兼容。
- 数据：保留 `/data/config` 与 `BACKUP_DIR` 的现有文件；新增版本化任务记录及自身升级状态。图标旧映射格式提供兼容读取。
- API：同步维护 `dockercopilot.api` 与实现；增加任务查询和必要的批量/异步入口，保留旧路径与主要响应字段；HTTP 状态统一为合法状态，业务码不再直接作为状态码。
- 运行：日志默认写入持久数据卷，保留标准输出；引入有限任务并发、超时和记录清理配置。
- 发布：自身升级包布局与 `start.sh` 对齐，验证 Linux amd64/arm64 和前端嵌入流程；沿用 `frontend-monorepo-build` 规格。
- 验证：现有回归测试、假 Docker daemon/HTTP 服务的故障测试、前后端契约测试、文件与日志验证。

## Non-goals

- 不引入多主机管理、执行代理、微服务、外部数据库、消息中间件或通用工作流引擎。
- 不引入 Workload/Revision 纳管模型，不承诺进程崩溃后自动续跑容器替换。
- 不将容器配置备份扩展为数据卷备份，不承诺撤销应用的数据迁移。
- 不引入自动定时更新、SSE 推送或新的容器业务能力；后台定时行为仍以镜像更新检查为主。
- 本变更描述一个完整目标和依赖有序的实施任务，不划分产品分期。
