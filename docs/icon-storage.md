# 图标文件与映射存储

图标上传和 `imageLogos.js` 映射由 `internal/settings` 的 `IconService` 统一处理。HTTP handler 只解析 multipart 请求、设置请求体上限并转换响应，不直接读写图标文件或映射。

## 文件位置和兼容性

- 图标文件目录：`/data/config/image`
- 映射文件：`/data/config/imageLogos.js`
- 新增图标文件名：`<UUID>.<png|jpg|jpeg|webp|gif>`
- 前端静态 URL：`/src/config/image/<UUID>.<扩展名>`
- 成功上传响应保持旧字段：`code=200`、`msg=Success`、`data=<UUID 文件名>`。
- `GET /api/icons` 继续返回 `code/msg/data`；已有映射无需重新上传即可读取。

用户原始文件名不会作为存储路径。扩展名只取自上传文件名，实际存储名由服务生成。

## 上传校验

服务允许 `png`、`jpg`、`jpeg`、`webp`、`gif`，并同时校验：

1. `imageName` 映射键：长度、非空、字符集和路径段。拒绝 `..`、绝对路径、反斜杠、空路径段等输入。
2. 扩展名：不在白名单时直接拒绝。
3. 文件实际大小：默认单文件上限 10 MiB。读取过程使用有限长度复制，超过上限的文件不会发布为图标。
4. 实际内容类型：用文件头检测结果与声明扩展名比较；伪装成图片的文本或其他内容会被拒绝。
5. multipart 请求总体大小：handler 使用 `http.MaxBytesReader` 限制整个请求，默认是单文件上限加 1 MiB 的 multipart 开销。`ParseMultipartForm` 的内存参数只决定临时文件落盘阈值，不作为上传体积上限。

文件先写入图标目录内的临时文件，完整写入并 `Sync` 后才通过同目录重命名发布为最终 UUID 文件。

## imageLogos.js 兼容读取

映射读取只接受以下结构：

```js
// 注释和空白可以保留
export const customImageLogos = {
  "nginx": "/src/config/image/nginx-custom.png",
  "registry.example:5000/team/app": "/src/config/image/team-app.webp",
};
```

解析器只接受带引号的字符串键和字符串值，允许普通注释、空白和尾随逗号。保留原映射声明之前和之后的文件内容。字符串转义按 JavaScript 规则解码，包括 `\xHH`、`\uXXXX`、Unicode 码点转义和成对 UTF-16 代理项；无效 UTF-8、未配对代理项和非法 Unicode 码点会被拒绝，避免重写时悄悄损坏旧映射。同一文件必须恰好有一个 `customImageLogos` 声明。不会执行文件中的 JavaScript，也不接受函数调用、变量引用、模板字符串或其他表达式作为映射值。

如果文件存在但无法按上述格式解析，读取和上传都会返回可定位的错误（包含行、列和原因），并且**不会**把映射覆盖为空对象。上传在读取映射阶段失败时不会创建新的图标文件。文件写入或清理失败的内部原因写入应用日志，HTTP 响应不暴露本机文件路径，也不记录上传内容。

## 并发和提交顺序

同一映射路径使用进程内共享锁（按规范化后的映射路径区分），不同请求不会创建彼此独立的锁。上传顺序为：

1. 在锁内读取并校验现有映射。
2. 校验新文件并写入临时文件。
3. 原子发布新图标文件。
4. 更新映射，并通过同目录临时文件、`Sync`、原子重命名发布 `imageLogos.js`。

如果映射保存失败，本次发布的图标文件会被删除；旧映射和旧图标保持不变。映射写入使用整文件原子替换，文件读者不会看到半写入内容。

该锁只保护单个进程。部署约束仍是单实例独占数据目录；多实例同时写同一映射路径不在支持范围内。

## 测试关注点

新增测试使用临时目录，不访问 `/data` 或线上服务，覆盖：

- 旧 `imageLogos.js` 格式和静态 URL 兼容读取；
- 并发上传不同键时映射不丢失；
- 损坏映射不被重置；
- 映射保存失败时回收新图标并保留旧映射/旧图标；
- 超限、伪装类型和路径穿越键被拒绝；
- 映射原子替换在发布前保持旧文件完整。
