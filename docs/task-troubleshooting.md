# 后台任务状态与排障

容器单项/批量更新、镜像清理、备份导出、备份恢复和程序升级均通过共享任务 API 查询状态。提交响应只表示任务已接受。页面保留原有行内进度、加载及成功/失败反馈，不增加任务列表或面板；逐项结果、恢复状态、警告和关联 ID 由 API 与日志提供。更新或恢复失败时不要假设没有任何变更。后台跟踪可恢复已保存任务 ID；容器更新会发现活动任务，程序升级使用提交前保存的 request ID 精确发现响应丢失的任务，不会重放修改请求。

架构升级曾引入的任务面板、展开/关闭按钮、ID 复制及发现失败提示区已撤回，见[页面兼容边界](ui-compatibility.md)。活动任务发现失败时仍在内部按有界退避重试，不因查询失败重新提交修改操作。

## 状态含义

- **已接受 / 执行中**：服务器仍报告活动状态。阶段和百分比用于说明当前记录，不代表精确剩余时间。
- **已完成**：服务器返回 `succeeded`。容器列表会重新加载。
- **失败**：服务器返回 `failed`。查看详细说明、错误、恢复结果和警告；“恢复结果”说明已确认的恢复状态，`unknown` 或 `failed` 表示仍需人工核对。
- **已中断**：服务器报告 `interrupted`，可能由客户端在服务重启或进度过期后合成，表示结果未知。不要假设操作已重放或自动恢复；按任务 API 和日志给出的容器 ID、当前状态和恢复提示检查 Docker，再决定人工处理。
- **连接中断，任务结果待确认**：只是状态查询或浏览器连接失败，不表示后台任务失败。页面使用退避间隔继续查询；连接恢复后展示服务端结果。不要因网络错误立即重复提交相同修改。
- **登录状态失效**：收到 401 后全局认证流程会返回登录页，任务 hook 停止轮询；重新登录并返回容器页后，以保存的任务 ID 继续查询。轮询停止期间结果仍待确认。
- **提交结果待确认**：提交没有收到可确认的响应。由内部跟踪继续查询，管理员按操作时间和资源名查日志；客户端不会自动重放 POST。

## 提供给管理员的信息

失败或中断时，提供操作时间、容器或文件名、原有页面提示及对应服务日志。日志中的 `taskId` 用于查询 `/api/progress/:taskid`；也可通过已认证的 `/api/tasks` 按条件查找记录。`requestId` 用于关联 HTTP 请求和后台任务日志。管理员结合错误、详细说明、恢复结果、警告和容器当前状态排查。公共任务投影不展示配置快照或容器环境变量。

任务文本来自服务端诊断字段。若内容包含访问令牌、凭据或其他敏感数据，请勿把截图或日志转发到公开渠道，并联系管理员按项目的数据处理流程排查。

## 服务重启或进度过期

普通操作进度只在内存中保存。HTTP 410 / `OPERATION_RESULT_EXPIRED` 表示进度不可再查询，操作结果未知，不代表 Docker 操作失败或没有发生。客户端会停止旧进度查询，不重放请求。按操作时间、请求 ID 与操作 ID 查看日志，再只读核对容器 ID、名称、镜像、运行/健康状态和端口。

没有任务目录扫描、损坏记录隔离或启动自动恢复。旧版本遗留的任务文件不再读取，也不会自动删除；它们可留作升级前的人工诊断证据。配置备份和用户数据仍按原有功能保留。程序自身升级的专用交接文件与恢复步骤见 [程序升级](program-update.md)。

## 拉取时报 `pull access denied for sha256`

如果日志的 `imageRef` 是裸 `sha256:...`，实际提交的是本地镜像 ID，而不是仓库地址。早期固定 ID 创建容器时没有保留更新来源，可能导致这一问题；它不能证明代理不可用或需要登录 Docker Hub。请在原有更新弹窗中填写正确的仓库引用（例如 `tailscale/tailscale:latest`）。修复后的版本会将更新来源写入新容器标签，供后续单项和批量更新使用；没有可靠来源时提前报错，不猜测仓库、不拉取名为 `sha256` 的仓库。本次错误若停在 `pulling-image`，尚未进入停止或替换旧容器的步骤。
