# 后台任务状态与排障

容器列表页的单容器更新使用共享任务跟踪器。提交响应只表示任务已接受；页面会显示排队、执行阶段和进度，任务结束后刷新容器数据。多个容器可同时跟踪，各自按稳定容器名保存任务 ID；容器替换后也会继续显示原任务结果。刷新页面后先恢复保存的任务 ID，并通过一次分页的 queued/running 任务发现补查未收到提交响应的任务，不会为每张卡片分别查询活动列表。卡片更新按钮和详情弹窗中的镜像更新共用这条流程。

批量操作、备份/恢复和程序更新入口还没有接入此任务面板，分别由后续页面任务迁移；它们当前的显示方式仍可能不同。

## 状态含义

- **排队中 / 执行中**：服务器仍报告活动状态。阶段和百分比用于说明当前记录，不代表精确剩余时间。
- **已完成**：服务器返回 `succeeded`。容器列表会重新加载。
- **失败**：服务器返回 `failed`。查看详细说明、错误、恢复结果和警告；“恢复结果”说明已确认的恢复状态，`unknown` 或 `failed` 表示仍需人工核对。
- **已中断**：服务器报告 `interrupted`，常见于进程重启后的未完成记录。不要假设操作已重放或自动恢复；按页面给出的容器 ID、当前状态和恢复提示检查 Docker，再决定人工处理。
- **连接中断，任务结果待确认**：只是状态查询或浏览器连接失败，不表示后台任务失败。页面使用退避间隔继续查询；连接恢复后展示服务端结果。不要因网络错误立即重复提交相同修改。
- **登录状态失效**：收到 401 后全局认证流程会返回登录页，任务 hook 停止轮询；重新登录并返回容器页后，以保存的任务 ID 继续查询。轮询停止期间结果仍待确认。
- **提交结果待确认**：提交没有收到可确认的响应。先查看页面按容器名恢复出的任务，或复制请求 ID 后交由管理员查日志；客户端不会自动重放 POST。

## 提供给管理员的信息

失败或中断时，展开任务面板并复制任务 ID 与请求 ID。任务 ID 用于查询 `/api/progress/:taskid` 或 `/api/tasks`；请求 ID 可用于关联服务端日志。把错误、详细说明、恢复结果、警告和容器当前状态一并提供给管理员。页面不会展示配置快照或容器环境变量。

任务文本来自服务端诊断字段。若内容包含访问令牌、凭据或其他敏感数据，请勿把截图或日志转发到公开渠道，并联系管理员按项目的数据处理流程排查。
