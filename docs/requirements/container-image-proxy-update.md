# 容器镜像代理更新需求

## 背景与目标

用户在 NAS 上管理使用 `latest` 标签的容器。DockerCopilot 通过仓库接口检查更新，点击更新后则由 NAS 的 Docker 引擎按标签拉取镜像。两次请求可能访问不同的镜像源。若检查发现摘要 B，而 Docker 拉取时仍得到本地已有的摘要 A，现有流程仍可能用 A 重建容器并显示更新成功。

本需求为容器更新增加一条可选路径。管理员在 DockerCopilot 服务配置中开启代理下载后，即使 NAS 的镜像源仍返回 A，只要 DockerCopilot 的代理能取得 B，系统就应使用 B 对应的平台镜像启动容器。代理无法取得 B 时，应在停止原容器前报告失败。适用入口为容器镜像更新，DockerCopilot 程序自身的版本更新另有独立流程。

## 更新策略

服务级设置分为两项。代理地址供更新检查和 Go 下载使用，留空时直连。镜像下载方式独立选择：默认由 NAS 的 Docker 引擎拉取，也可以选择 Go 下载后导入。下表中的开启与关闭仅指是否采用 Go 下载。

| 服务配置 | 镜像获取方式 | 容器替换方式 |
| --- | --- | --- |
| 未配置或关闭 | 沿用当前 Docker `ImagePull`，由 NAS 按请求中的仓库和标签拉取 | 沿用当前容器更新和旧容器保留策略 |
| 开启 | Go 通过 DockerCopilot 的代理按目标摘要下载，生成临时镜像包，调用 Docker `ImageLoad` 导入并校验 | 校验成功后复用现有容器重建流程 |

## 代理模式的更新流程

1. **锁定用户要更新的镜像。** 检查更新时，后端保存完整仓库名、标签和检查到的顶层 Digest。点击更新后，将该目标固定到本次任务。如果用户改了镜像名或标签，或没有对应的检查记录，先通过代理解析实际目标，再固定摘要。即使下载期间 `latest` 移动，本次任务仍使用已固定的版本。
2. **选择平台并下载。** 对多架构镜像，从已固定的索引中选择与原容器镜像相符的操作系统、CPU 架构和必要的架构变体；对单平台镜像直接核对平台。Go 使用后端代理获取仓库认证信息、清单、配置和镜像层，核验所下载内容的摘要，再生成 Docker 可装载的临时包。目标平台缺失或代理不可用时，任务结束并显示原因，避免静默回退到 NAS 的镜像源。
3. **导入并核实镜像。** 临时包携带目标仓库名和标签。后端读取 Docker 装载结果，确认目标标签对应的本地 Image ID 与所选平台清单中的配置摘要一致。顶层索引摘要、平台清单摘要和配置摘要分别用于确认版本、平台和本地镜像身份。
4. **替换容器。** 完成导入校验后，才停止旧容器并用原名称、挂载、端口及网络配置创建新容器。启动后核对新容器使用的 Image ID 与已验证的 ID 一致，再报告成功。重复点击或并发更新同一标签时，每个任务使用的镜像必须与自己的目标匹配。旧容器按现有 `DelOldContainer` 设置处理。
5. **清理临时文件。** 这里的“清理镜像”专指删除本次任务下载的临时包、分片及未完成文件。Docker 完成装载并校验后即可释放这些文件。失败时同样清理本次任务的文件。新镜像保留在 Docker 的本地镜像库中，供容器运行、重启和后续检查使用。

## 后续检查与故障反馈

- **识别已更新版本。** 代理更新成功后，持久记录仓库、标签、平台、上游目标摘要及已投入使用的本地 Image ID。下次检查时，即使 NAS 导入镜像后缺少 `RepoDigests`，仍能识别这个版本。只有当前镜像与记录匹配时才使用这份记录；手动换镜像后重新判断。DockerCopilot 重启后仍能继续检查。
- **进度和错误。** 沿用现有任务进度入口，显示解析目标、下载、导入、校验、重建及最终结果。下载失败、空间不足、平台不匹配、导入失败、校验失败时，指出失败阶段和原因。重建期间失败时，报告新旧容器的实际状态。日志可按任务核对目标仓库、平台、Digest 和本地 Image ID，并对代理凭据及仓库令牌脱敏。
- **NAS 存储。** 下载期间需要同时容纳临时包和 Docker 导入的数据。以流式读写避免将整个镜像载入内存。进程异常退出后，下次启动应能清理已中断任务的残留文件，并保护仍在使用的任务目录。

## 验收场景

| 场景 | 可观察的结果 |
| --- | --- |
| 服务配置省略开关或显式关闭，用户点击更新 | 任务走原有 `ImagePull` 路径 |
| 服务开启代理下载，分别从页面和旧客户端更新两个容器 | 两个请求均沿用原有参数，后端自动为两个任务选择代理下载 |
| 将服务开关关闭，配置生效后通过同一客户端再次更新 | 新任务恢复使用 `ImagePull` |
| 服务已开启代理下载，NAS 对 `latest` 返回旧摘要 A，检查和 Go 代理均可取得新摘要 B | 新容器运行 B 中目标平台的镜像，任务可核对目标摘要及实际 Image ID |
| 点击后 `latest` 从 B 变为 C | 本次仍安装 B；若 B 已不可下载，在停止原容器前报告失败 |
| 同一标签含 amd64 和 arm64 版本 | 两种 NAS 分别导入与原容器平台相符的镜像；缺少匹配平台时原容器继续运行 |
| 下载中断、临时空间不足、Docker 导入报错或镜像校验不符 | 任务标明失败阶段，原容器继续运行，任务临时文件得到清理 |
| 重建成功后查看磁盘并重启容器 | 本次临时包已删除，新容器仍可基于已导入的镜像正常重启 |
| 导入后的镜像缺少 `RepoDigests`，重启 DockerCopilot 并再次检查 | 上游仍为 B 时显示已是最新；上游更新到 C 后能再次提示更新 |
