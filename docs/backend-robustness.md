# 单主机后端与健壮性

本次调整以 v2.2.2 的使用能力为边界：容器生命周期与更新、镜像管理、配置备份恢复、端口便捷访问、图标和程序升级继续保留。页面布局、导航与入口保持现状。

## 结构

HTTP handler 负责解析和响应，logic 组织业务服务。`svc` 统一装配 Docker 客户端、缓存、容器/镜像/备份/端口/图标服务，以及进程内操作执行器。业务服务不依赖 HTTP 层；旧 `utiles` 和进度入口保留为兼容适配。

后台操作默认最多并发 2 个，没有等待队列、磁盘任务数据库、启动任务扫描或历史任务管理。操作进度与私有配置快照均有内存上限，普通终态进度保留 10 分钟。HTTP 断线不取消后台操作；服务退出后普通操作结果需结合 Docker 状态和日志核对，不自动重试。

## 保留的保护

- 容器 ID 与名称统一协调，活跃的等价更新复用操作，冲突请求拒绝。
- 单项与批量更新共用检查点和恢复映射；先拉取并固定镜像 ID，保存当前配置，再替换与验证。
- 新实例验证并提交后，旧容器清理失败仅记警告。提交前失败则等待原回调退出后尝试即时恢复。
- 超时取消上下文，回调未退出前不释放占用或并发额度，避免原操作和恢复并行修改同一容器。
- 原有业务配置原子写入、备份路径限制、证书验证和日志脱敏继续保留。
- 程序自身升级单独保留 launcher 交接标记和 ready 结果；新进程验证运行二进制和 HTTP 就绪后重建该次升级结果。

请求 ID、操作 ID、目标、阶段、耗时、错误和恢复结果串联诊断日志。查询丢失的进度返回 HTTP 410 / `OPERATION_RESULT_EXPIRED`，客户端提示结果未知并停止旧查询，不重复提交操作。

## 代理与配置

应用 HTTP 请求使用 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`；实际镜像拉取使用 Docker daemon 自身的代理。见 [代理配置](docker-proxy.md)。旧任务目录、队列和历史保留配置兼容读取但不再生效，不影响现有备份、日志和端口配置路径。

## 本地验证

完成内部 Go 全套测试、根包嵌入资源测试、相关并发检测、47 项前端测试、前端构建、六页浏览器 mock 冒烟、launcher 隔离夹具，以及 Linux amd64/arm64 交叉构建。新回归覆盖进度失效、代理与 NO_PROXY、内存容量和 TTL、恢复超时阻止批次后项、活跃操作去重与备份占用。

验证使用本地假 Docker HTTP 服务和临时目录；没有在真实 Docker 主机执行容器更新或在线替换二进制。进程崩溃后不提供通用恢复保证，管理员应按日志与实际容器状态判断结果。
